The Objective Coupling Scoring Model: Full Mechanism Data for 65 Languages

The complete, auditable per-language mechanism-presence data behind every score in the 65-language coupling comparison — reproduce any score from first principles.

1 The Objective Coupling Scoring Model: Full Mechanism Data

Companion to: The Great Language Smackdown: 65 Languages Through the Coupling Lens

The main article ranks 65 languages by language-imposed coupling. This companion publishes the complete per-language mechanism-presence data behind every score, so any reader can reproduce any number from first principles — no trust required.

The coupling analysis this model operationalizes — coupling as access to a shared resource, and the derivation of a modularisation directive from coupling — is developed in the published coupling papers [1], [2].

Analysis date: June 2026. All languages are assessed against the version shown.

1.1 How a score is computed

The model is a capped-sum-per-dimension inventory:

  1. A fixed mechanism inventory, each mechanism with a fixed weight.
  2. For each language, every mechanism is marked present or absent (a factual determination).
  3. Within each of the six Core dimensions (and eight Meta dimensions), the present weights are summed and clamped to at most −15.
  4. Score = 100 − Σ(capped per-dimension contributions).

The cap equals the High weight (−15), so a dimension never costs more than one severe mechanism. This keeps scores bounded (minimum Core = 10), monotone (adding a mechanism never helps), and discriminative (no collapse to zero).

1.1.1 Score bands

Because the model is a fixed-inventory capped-sum-per-dimension model, the bands follow directly from the mechanism weights:

  • 90+: No dimension contains a severe (High) mechanism, and at most one dimension reaches even −8. Near the irreducible floor.
  • 75–89: No dimension reaches −15; a small number of moderate (−8) mechanisms spread across dimensions.
  • 60–74: At least one dimension caps at −15 (a severe mechanism), or several dimensions carry moderate mechanisms.
  • 45–59: Two or three dimensions cap at −15, or one severe mechanism plus several moderate across other dimensions.
  • Below 45: Three or more dimensions cap at −15 — the language’s design trades separation of concerns for other goals (simplicity, flexibility, ubiquity, or direct hardware access).

1.1.2 Dimension sub-scores

The dimension sub-scores shown in the main article’s comparison matrices are the per-dimension contribution: 100 minus the capped sum of the present mechanisms in that dimension only. They are not independent scores — they are the building blocks of the composite, so a language’s Core score always equals 100 minus the sum of its six capped per-dimension contributions.

1.3 How to reproduce a score

To reproduce any score: read the language’s present Core mechanisms, group by dimension, sum and clamp each dimension to −15, sum the six clamped values, subtract from 100. Repeat for Meta with its eight dimensions.

Worked example — Java (Core 53): present Core = T7, T10, C2, M2, M3, M4, Er2, K3.

Dimension Present Clamped sum
Type T7(−4) + T10(−8) −12
Construction C2(−4) −4
Memory M2(−8) + M3(−4) + M4(−8) = −20 −15 (clamped)
Error Er2(−8) −8
Concurrency K3(−8) −8
Platform — 0

Total clamped = 12+4+15+8+8 = 47. Core = 100 − 47 = 53. ✓
