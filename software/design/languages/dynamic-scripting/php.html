PHP (8.5)

This assessment applies the coupling account — coupling as access to a shared resource, and the coupling floor [1], [2] — and the knowledge-embodiment theorem [3]; the language is assessed against its official reference [4].

1 Assessment

This page assesses PHP in five parts: core coupling — what the language’s own constructs force; ecosystem coupling — what the surrounding platform, tooling, and community cost; engineering readiness — whether the artifact can be reproduced, verified, observed, worked in quickly, connected to other languages, and governed openly; the profile — the unscored facts a score cannot express; and the scoring detail — the mechanism marks and the arithmetic behind every score. A ✅ bullet marks a construct that helps. A ⚠️ or ❌ bullet marks a cost; the scoring model does not price every cost named here.

Core coupling 28/100 · Ecosystem coupling 69/100 · Engineering readiness 84/100

1.1 Core coupling

1.1.1 Type

  • ⚠️ Type declarations (PHP 7+): Gradual typing, improving
  • ✅ Interfaces decouple: Can program to interfaces
  • ❌ Weak typing historically: Type juggling couples
  • ⚠️ Traits: Multiple inheritance-like, can couple
  • ❌ Inconsistent stdlib: strpos vs str_replace couples to memorization
  • ✅ Namespaces scope every name: A namespace declaration qualifies a class, function, or constant, so two libraries can define the same short name
  • ⚠️ Magic methods can hide coupling: __get, __call obscure behavior

1.1.2 Construction

  • ⚠️ Constructors can have side effects: No enforcement
  • ❌ No immutability by default: Everything mutable
  • ⚠️ Dependency injection available: Frameworks support it
  • ❌ Global state tempting: $_GET, $_POST, $_SESSION couple

1.1.3 Memory

  • ✅ Reference counting: Immediate deallocation when references drop to zero
  • ✅ Cycle collector: Detects and breaks circular references
  • ✅ Request-scoped by default: Each request has isolated memory, cleared after request
  • ❌ Long-running processes leak: Traditional PHP has no long-lived processes, but Swoole/ReactPHP do
  • ✅ No manual memory management: Can’t have use-after-free in pure PHP
  • ⚠️ Extensions can leak: C extensions may have memory issues

1.1.4 Error

  • ❌ Exceptions unchecked: No type tracking
  • ⚠️ Error vs Exception confusion: Two error mechanisms couple
  • ❌ @ operator suppresses errors: Hides coupling
  • ⚠️ Modern frameworks handle better: Laravel/Symfony impose discipline

1.1.5 Concurrency

  • ❌ Shared-nothing by default: Each request is separate process
  • ✅ Fibers (PHP 8.1): Built-in cooperative concurrency — enables async I/O without external extensions
  • ⚠️ No built-in async event loop: Fibers need a framework (ReactPHP, Swoole) for full async; however Revolt/Amp provide fiber-based event loops
  • ❌ Global state couples across requests: Sessions, databases

1.1.6 Platform

  • ✅ No company owns the language: PHP is maintained by The PHP Group and released under the PHP Licence, a permissive BSD-style licence
  • ✅ The reference implementation is free software: The Zend Engine is developed in the open and shipped by every Linux distribution
  • ✅ The interpreter is portable: PHP runs on Linux, macOS, and Windows, under Apache, nginx through PHP-FPM, and IIS
  • ✅ Commodity hosting provides it: Most shared hosts include a PHP runtime, so deployment needs no platform purchase
  • ✅ No single distribution is required: Distribution packages, official builds, and vendor bundles run the same language

1.1.7 Trade-offs (not coupling)

  • The language began as a page preprocessor: PHP grew from a templating tool, so markup and logic still share one file — a design origin whose cost is mixed presentation and behaviour
  • Every variable carries a $: The sigil marks a variable at a glance and cannot be omitted, a notation decision rather than a type-system one
  • The core library assumes one short request: Functions such as header() and session_start() act on the current request, an assumption that costs when the same code must run in a long-lived worker
  • Frameworks define the architecture: PSR interfaces and the Laravel or Symfony conventions shape practice more than the language does — an ecosystem convention, not a dependency the language forces
  • Feature growth is version-gated: Enums, readonly classes, and property hooks arrive release by release, so the style a codebase may use follows its minimum supported version — an evolution cost, not a coupling

1.2 Ecosystem coupling

1.2.1 Performance

  • ⚠️ Interpreted: Slower than compiled languages
  • ✅ PHP 8+ JIT: Significant improvements for CPU-bound workloads
  • ⚠️ Shared-nothing: Each request starts fresh (couples to memory)
  • ✅ Fibers: Cooperative concurrency without process overhead
  • ⚠️ OPcache helps: But couples deployment to caching

1.2.2 Ecosystem

  • ✅ Composer: Good package manager
  • ✅ Large ecosystem: Packagist has many packages
  • ✅ Laravel, Symfony: Mature frameworks
  • ✅ IDE support: PHPStorm excellent, VSCode good
  • ⚠️ Quality varies: Many low-quality packages

1.2.3 Evolution

  • ✅ Improving rapidly: PHP 8.1-8.5 added enums, fibers, readonly, property hooks, asymmetric visibility, clone with, pipe operator
  • ✅ Regular releases: Yearly cadence
  • ⚠️ Legacy burden: Must support old code (PHP 5.x still in the wild)
  • ❌ Inconsistent stdlib: function_name vs functionName — PHP 8.x is standardizing but still inconsistent

1.2.4 Domain

  • ✅ Excellent for traditional web: WordPress, Drupal, Laravel
  • ⚠️ Backend only: Can’t do frontend (obviously)
  • ✅ Fibers enable async: Modern PHP can do async I/O natively
  • ⚠️ CLI possible: But uncommon relative to Python/Ruby
  • ❌ No systems programming: Not suitable

1.2.5 Learning

  • ✅ Very gentle: Easy to start
  • ✅ Lots of resources: Tutorials, documentation
  • ⚠️ Bad habits easy: Superglobals, $ prefix confusion
  • ✅ Quick productivity: Deploy immediately

1.2.6 Syntax

  • ⚠️ C-like syntax: Familiar but verbose
  • ✅ Property hooks (8.4): Eliminates getter/setter boilerplate
  • ✅ Asymmetric visibility (8.4): Clean access control
  • ❌ Superglobals: $_GET, $_POST everywhere
  • ❌ Inconsistent stdlib: Hard to remember function names

1.2.7 Testing

  • ✅ PHPUnit: Industry standard
  • ⚠️ Xdebug: Works but setup needed
  • ✅ Property hooks + readonly: Easier to test (less setup)
  • ⚠️ Error reporting: Improving with strict types

1.2.8 Security

  • ✅ Memory safe: GC prevents memory bugs
  • ❌ SQL injection: Easy to do wrong (prepared statements help but not enforced)
  • ❌ XSS: Template systems help but not enforced
  • ❌ Superglobals: Injection attack surface
  • ⚠️ Modern frameworks help: But not language-level

1.4 Profile

Unscored, and kept separate from every score on purpose. The profile records what a mechanism price cannot express: what a running program costs, how well a coding model and an agent work in the language, and whether a safety-critical path exists.

1.4.1 Energy and cost

What this axis asks: what does a running program cost in energy and time?

  • ❌ Interpreted by default: the slowest class in the energy and time benchmarks [5]; a causal re-analysis attributes most of the gap to execution time [6].

1.4.2 AI and agent readiness

What this axis asks: how well does a coding model and an agent work in this language?

  • ✅ A large training corpus and strong code-generation results: models write this language well [7], [8].

1.4.3 Safety certification

What this axis asks: is there a certified or standards-qualified path to a safety-critical system?

  • ⚠️ No certified or standards-qualified path for safety-critical systems.

Verdict: PHP is steadily improving its coupling profile. Enums (8.1), readonly classes (8.2), property hooks and asymmetric visibility (8.4) add compile-time structure. Fibers (8.1) enable built-in async. Superglobals create pervasive coupling. Shared-nothing architecture prevents temporal coupling but wastes resources. Main strength: simplicity for web, rapid improvement cadence. Main weakness: superglobals, inconsistent stdlib, no standard async runtime.
