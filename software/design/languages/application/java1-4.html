Java (Java 1.4)

This assessment applies the coupling account — coupling as access to a shared resource, and the coupling floor [1], [2] — and the knowledge-embodiment theorem [3]; the language is assessed against its official reference [4].

Snapshot Java 1.4 — released 6 February 2002 · lifecycle retired (the last release before generics)

Family Java — shelf: Application

The language’s main business is building general application software, with a managed runtime or a rich standard library. A shelf groups; it does not classify — the tags below carry every use, paradigm, and platform of this snapshot.

Trajectory 1.4 (6 February 2002 — assertions and NIO; the last release before generics) · 5 (30 September 2004 — generics, annotations, enums) · 6 (11 December 2006 — library and performance release; no language change) · 7 (28 July 2011 — diamond, try-with-resources, invokedynamic) · 8 (18 March 2014 — lambdas and streams; LTS) · 11 (25 September 2018 — module system and var; LTS) · 17 (14 September 2021 — records and sealed types; LTS) · 21 (19 September 2023 — virtual threads; LTS) · 25 (16 September 2025 — scoped values and the compact source file; LTS) · 26 (17 March 2026 — runtime-only release) · 27 (15 September 2026 — runtime-only release)

1 Assessment

This page assesses Java in five parts: core coupling — what the language’s own constructs force; ecosystem coupling — what the surrounding platform, tooling, and community cost; engineering readiness — whether the artifact can be reproduced, verified, observed, worked in quickly, connected to other languages, and governed openly; the profile — the unscored facts a score cannot express; and the scoring detail — the mechanism marks and the arithmetic behind every score. A ✅ bullet marks a construct that helps. A ⚠️ or ❌ bullet marks a cost; the scoring model does not price every cost named here.

Core coupling 64.6/100 · Ecosystem coupling 78.5/100 · Engineering readiness 77.2/100

1.1 Core coupling

1.1.1 Type

  • ✅ Interfaces decouple specification from implementation: A program is written against an interface, and an implementation is supplied at run time
  • ❌ There are no generics (before Java 5): A collection holds Object, so every read is a cast the compiler cannot check (T5)
  • ⚠️ Reflection reads the structure at run time: java.lang.reflect reaches a field or a method by name, outside the type check (T7)
  • ❌ Null is in every reference: NullPointerException is possible wherever a reference is used, and no non-nullable type says otherwise (T10)
  • ❌ There is no sum type: A closed set of cases is a class hierarchy, and a switch over an int constant is not checked for exhaustiveness (T4)
  • ❌ A package is not a boundary: Every public class is reachable on the classpath, and nothing declares what a library exports (T11)
  • ⚠️ Inheritance is available: Unchecked class extension couples a subclass to its superclass unless the class is final
  • ❌ char is a UTF-16 code unit and String.length counts units (JLS); code-point APIs are the opt-in (T15)

1.1.2 Construction

  • ❌ A field is mutable unless declared final: A setter is the ordinary way to change state (C2)
  • ✅ A factory method states the contract: A static method returns a cached instance or a subtype
  • ⚠️ A complex object needs a builder: A telescoping constructor couples the call site to the field order
  • ❌ Collection order is unpinned: HashMap iterates in a hash-dependent order the specification does not fix, and the ordered map is the opt-in a disciplined team must choose (C5)
  • ❌ One value, many names: every object is reached through references, an array’s buffer is shared by assignment, and no declaration names the alias set — a defensive copy is a discipline, not a type (C6)
  • ❌ Class initialization is first-touch; JLS 12.4.1 documents the cycle: a thread observes zero fields, and a cycle can deadlock (C8)

1.1.3 Memory

  • ✅ The JVM collects garbage: An unreachable object is reclaimed, so a program never frees memory by hand
  • ✅ There is no manual deallocation: A dangling pointer cannot occur in managed code
  • ❌ A collection pause is part of the timing: The collector’s schedule is not the program’s (M2)
  • ⚠️ The default collector stops the world: A serial collector pauses every thread
  • ⚠️ JNI reaches outside the heap: A native call is unchecked
  • ✅ The class entered the declared surface: Java 1.4 made OutOfMemoryError a thrown value (documented) — the memory-exhaustion patch moved the fault into the catchable class, and the JLS/JavaDoc contract names it (Er6)

1.1.4 Error

  • ✅ A checked exception states a recoverable failure: throws IOException puts the failure in the signature
  • ❌ An unchecked exception bypasses the signature: A RuntimeException can leave any method, so a caller cannot read the failure set from the type (Er2)
  • ❌ Try-catch does not compose: A failure is handled where it is caught, not mapped over (Er4)
  • ⚠️ finally closes the resource: There is no try-with-resources before Java 7

1.1.5 Concurrency

  • ✅ A Thread is the unit of concurrency: A task is a Runnable handed to a new thread, and a pool is hand-written
  • ✅ wait and notify are the primitives: A monitor and a condition variable are in the language
  • ⚠️ java.util.concurrent does not exist yet: A latch, a queue, and an executor are hand-written or bought
  • ⚠️ Shared mutable state is the default: synchronized, volatile, and manual locks remain, and nothing detects a race (K3)
  • ❌ A task holds a platform thread: Each task reserves one until it ends, so the number of tasks is bounded by the platform; Java 21’s virtual threads remove the cost (K6)

1.1.6 Platform

  • ✅ The specifications are public: The Java Language Specification and the JVM Specification are standards any conforming implementation may implement
  • ✅ Several vendor runtimes run the same class files: Sun, IBM, BEA, and Hewlett-Packard each shipped a JVM
  • ✅ Bytecode is portable: A class file runs on every platform that hosts a JVM

1.1.7 Trade-offs (not coupling)

  • Checked exceptions vs. composition: Explicit errors do not compose natively, and a switch over a hierarchy is not checked for exhaustiveness
  • Backward compatibility vs. modern features: Old codebases lag behind the language, and the 1990s APIs stay in service
  • Null as default vs. safety: Every reference can be null, and nothing in the type marks the check
  • A collection holds Object: A read is a cast, so the element type is a convention the compiler cannot check
  • Inheritance vs. composition: A hierarchy is the only way to express a closed set of cases, and the compiler does not check it

1.2 Ecosystem coupling

1.2.1 Performance

  • ✅ The JIT optimises the hot path: A method is compiled after it proves hot
  • ⚠️ A GC pause is part of the timing: The collector decides when memory returns (R2)
  • ⚠️ Startup pays for interpretation: A cold JVM interprets until the JIT compiles (R3)
  • ✅ The JDK ships a profiler: hprof and a thread dump are in the distribution

1.2.2 Ecosystem

  • ✅ Ant builds the classpath: A build is an XML script, and a dependency is a jar in a directory
  • ⚠️ An application server is the deployment target: J2EE and EJB set the architecture
  • ⚠️ The ecosystem carries old APIs: The enterprise stack keeps 1990s-era interfaces in service beside a current one (Ec7)
  • ✅ The IDE is mature: IntelliJ IDEA and Eclipse compile and debug in 2002
  • ✅ The class file carries a published promise across JDK releases [4] (Ec8)
  • ✅ Serialized objects cross on a published promise: the stream carries the format version and a per-class serial version UID, and the specification states the current protocol is fully backward and forward compatible, read by JDK 1.1.7 and later [5] (Ec9)

1.2.3 Evolution

  • ✅ Backward compatibility is strong: A class file from an older release still runs
  • ✅ A feature release was deliberate: Java 1.4 was one of the multi-year releases, and it added assertions and NIO
  • ⚠️ There is no preview mechanism: An experimental feature is a flag or an incubator module

1.2.4 Domain

  • ✅ Excellent for backend and enterprise work: The standard choice for a large service
  • ✅ Strong for distributed systems: Mature frameworks and a mature runtime
  • ⚠️ A rich client is Swing, and the web path is an applet: A browser plugin runs it, and the plugin is a support burden
  • ⚠️ Systems programming is out of reach: A collector and a managed runtime

1.2.5 Learning

  • ✅ Widely taught: Courses, books, and a large body of examples
  • ✅ The documentation is exhaustive: Javadoc and the tutorials
  • ⚠️ The surface is large: The language, the standard library, and the enterprise APIs (L2)

1.2.6 Syntax

  • ⚠️ A cast accompanies every collection read: A type is recovered by a cast the compiler cannot check
  • ⚠️ A type is spelled out: The declaration names the type on both sides
  • ⚠️ Checked exception syntax is verbose: A signature carries the failure set

1.2.7 Testing

  • ✅ JUnit is the standard test runner: Mature and ubiquitous
  • ✅ Excellent debuggers: Step-through and breakpoints in the IDE and on the command line

1.2.8 Security

  • ✅ Memory safe: The collector prevents a use after free
  • ✅ Type safe: A static check runs before the program
  • ⚠️ Deserialization is an attack path: A crafted stream constructs an object graph the program did not choose
  • ⚠️ A null check is the caller’s: A reference can be null, and nothing states the guard
  • ❌ Integer arithmetic is two’s-complement wraparound by specification (JLS 15.7.2), silent in a shipped build (Q4)

1.4 Profile

Unscored, and kept separate from every score on purpose. The profile records what a mechanism price cannot express: what a running program costs, how well a coding model and an agent work in the language, and whether a safety-critical path exists.

1.4.1 Energy and cost

What this axis asks: what does a running program cost in energy and time?

  • ⚠️ Runs on a virtual machine, above native code in the energy and time benchmarks [6]; a causal re-analysis attributes most of the gap to execution time [7].

1.4.2 AI and agent readiness

What this axis asks: how well does a coding model and an agent work in this language?

  • ✅ A large training corpus and strong code-generation results: models write this language well [8], [9].

1.4.3 Safety certification

What this axis asks: is there a certified or standards-qualified path to a safety-critical system?

  • ✅ A standards-qualified toolchain or an established safety standard covers this language.

Verdict: Java 1.4 is the last release before generics, annotations, and enums, and the score is shaped by that absence: a collection holds Object, so every read is a cast the compiler cannot check, and a closed set of cases is a hierarchy or an int constant that nothing verifies. It does have interfaces, a checked exception channel, a managed heap, and portable bytecode. Main strength: a managed, standardised runtime with a real interface boundary. Main weakness: no generics, no module boundary, and a null in every reference.

Note: The score reflects Java 1.4 as assessed: no generics, no annotations, no enums, and no module boundary.
