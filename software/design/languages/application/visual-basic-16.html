Visual Basic 16 (.NET)

This assessment applies the coupling account — coupling as access to a shared resource, and the coupling floor [1], [2] — and the knowledge-embodiment theorem [3]; the language is assessed against its official reference [4].

Snapshot Visual Basic (.NET) — released 8 November 2021 · lifecycle supported

Family Visual Basic — shelf: Application

The language’s main business is building general application software, with a managed runtime or a rich standard library. A shelf groups; it does not classify — the tags below carry every use, paradigm, and platform of this snapshot.

Trajectory 1.0 (May 1991 — first release) · 6.0 (1998 — the last classic release) · 16 (8 November 2021 — shipped with Visual Studio 2022)

1 Assessment

This page assesses Visual Basic .NET in five parts: core coupling — what the language’s own constructs force; ecosystem coupling — what the surrounding platform, tooling, and community cost; engineering readiness — whether the artifact can be reproduced, verified, observed, worked in quickly, connected to other languages, and governed openly; the profile — the unscored facts a score cannot express; and the scoring detail — the mechanism marks and the arithmetic behind every score. A ✅ bullet marks a construct that helps. A ⚠️ or ❌ bullet marks a cost; the scoring model does not price every cost named here.

Core coupling 71.0/100 · Ecosystem coupling 80.2/100 · Engineering readiness 86.4/100

1.1 Core coupling

1.1.1 Type

  • ❌ Option Strict Off is the default: Under it an implicit narrowing conversion and a late-bound Object call compile, and the type is resolved when the statement runs (T2)
  • ✅ Option Strict On removes the late-bound path: The same code does not compile until the conversion or the reference is written explicitly
  • ✅ Interface and Implements separate a contract from its implementation: A class names the interface members it supplies
  • ✅ A nullable value type states an absence: Integer? is Nullable(Of Integer), and HasValue and Value test and read it
  • ❌ Nothing is compatible with every reference type: A reference may be Nothing, no declaration requires a test before use, the language offers no nullable reference annotation, and for a string "" = Nothing is True (T10)
  • ⚠️ A class hierarchy couples a derived class to its base: Inherits binds a class to the base’s virtual members, and an Interface with Implements is the alternative that avoids the chain

1.1.2 Construction

  • ✅ Sub New is a real constructor: A class declares it, Overloads gives several signatures, and MyBase.New runs the base constructor
  • ✅ ReadOnly and Const mark a fixed value: A ReadOnly field is set once, and a Const is fixed at compile time
  • ❌ Mutability is the default: A Dim variable and a property are writable, and only an explicit ReadOnly or Const changes that (C2)
  • ✅ A Structure is a value type with its own constructor: A copy of a structure is a copy of its values, and it is not collected
  • ✅ Using bounds the life of a resource: The block calls Dispose on every exit path
  • ⚠️ WithEvents binds the handler object to its source: A WithEvents field is tied to the events of one declared type, and Handles lists the events it answers, so the subscription is written into the declaration

1.1.3 Memory

  • ❌ The garbage collector decides when memory returns: A reference is reclaimed after it becomes unreachable, and a collection pause is possible (M2)
  • ❌ No release runs at the end of a scope: A class has a finalizer at best, whose time is not defined, and there is no deterministic destructor (M3)
  • ❌ No ownership model: A reference may alias, and nothing in the type states who releases the object (M4)
  • ✅ Using gives deterministic release for an IDisposable: The block calls Dispose on every exit, including the exceptional one
  • ✅ IDisposable is the stated protocol for a native resource: A type that holds a handle states its release method
  • ⚠️ A finalizer delays the collection of its object: The object survives one extra collection while the finalizer queue is drained

1.1.4 Error

  • ❌ The exceptions are unchecked: No method signature states the exceptions it may raise, so a Try is a convention (Er2)
  • ❌ A failure can be discarded by design: On Error Resume Next and an empty Catch both let a failure pass with no effect (Er3)
  • ✅ Try/Catch/Finally is a structured path: The Catch block holds the recovery code and Finally runs on every exit
  • ✅ The failure is selected by type: Catch ex As IOException chooses by exception type, and ex.InnerException carries the cause
  • ⚠️ The legacy On Error GoTo form remains: It binds the recovery to a line label and a sequence, beside the structured form
  • ⚠️ An Async failure arrives at the Await: An exception in an awaited task surfaces at the await, so the Try block must span it

1.1.5 Concurrency

  • ❌ Synchronisation is manual with no race detection: SyncLock guards a block, and the compiler analyses no program for a race (K3)
  • ✅ SyncLock is a language construct: It takes a lock on an expression and releases it at the end of the block
  • ✅ Async and Await state the suspension point: An asynchronous call reads as a sequence, and the language marks where it yields
  • ✅ The task and thread types come from the runtime: Task, Thread, and the thread pool are .NET types the language uses directly
  • ⚠️ The lock order is not stated: SyncLock names a lock and not an order, so a deadlock is a design concern outside the language
  • ⚠️ An event handler runs on the raising thread: An event raised on a worker thread runs the handler there, and the UI-thread rule is a framework convention
  • ❌ Thread reserves an operating-system thread: Each task holds one for its whole life (K6)

1.1.6 Platform

  • ✅ The compiler emits a portable .NET assembly: The resulting .dll or .exe runs wherever the .NET runtime runs
  • ✅ The runtime runs on Windows, Linux, and macOS: The same assembly runs on each, so the language is not bound to one operating system
  • ✅ The class library is reachable: An assembly with a public surface can be consumed from Visual Basic
  • ✅ The project system is the common one: A .vbproj is an SDK-style project built by dotnet build
  • ⚠️ A few newer features have no Visual Basic form: Nullable reference annotations and static abstract interface members have no equivalent syntax, so a consumer of a library that requires them needs a wrapper
  • ⚠️ Windows Forms and WPF target Windows only: A GUI project on either framework runs on Windows

1.1.7 Trade-offs (not coupling)

  • Late binding is the pragmatic COM path: Option Strict Off around an Office object model avoids an interop reference, which is why the setting survives
  • The Visual Basic 6 heritage is deliberate: On Error, My, and the forms designer are continuity choices for the existing developer base
  • Verbosity buys explicitness: End If and End Sub are redundant, and the end of every block is visible
  • The design-time form designer is a tool: The layout is a tool feature rather than a language mechanism
  • A port to C# is mechanical: The constructs map closely, and the effort is the trade for leaving the language line
  • A frozen language is stable for existing code: No feature churn reaches a maintained program

1.2 Ecosystem coupling

1.2.1 Performance

  • ✅ The compiler emits IL and the runtime compiles it: The hot path becomes machine code through the just-in-time compiler
  • ✅ The collector is generational: A short-lived object is reclaimed cheaply
  • ✅ The runtime library supplies the fast paths: StringBuilder and the asynchronous I/O APIs are available to a Visual Basic program
  • ⚠️ The first call of a method is the slowest: Compilation happens on first use, so start-up includes a warm-up
  • ⚠️ Boxing and string concatenation allocate: An Object-typed value and a repeated & produce garbage on the heap
  • ⚠️ A collection pause is possible on a large heap: The collector’s pause is outside the program’s control (R2)

1.2.2 Ecosystem

  • ✅ NuGet is the package manager: A dependency is declared in the project and restored by dotnet restore
  • ✅ The IDE is Visual Studio: Editing, refactoring, debugging, and the designer are integrated, and the free edition supports Visual Basic
  • ✅ The class library is large and documented: I/O, networking, collections, and UI are covered by the runtime
  • ✅ The compiler ships with the platform: vbc is maintained with the .NET SDK
  • ⚠️ The published example is usually C#: A library’s documentation and samples are C#, and a Visual Basic consumer translates them
  • ⚠️ New libraries are rarely written in Visual Basic: The language’s share of new code is small
  • ✅ CLR metadata carries a published promise: VB.NET compiles to IL under the runtime’s standardised format [5], [6] (Ec8)
  • ❌ Stored payloads bind to the runtime: VB.NET runs on the .NET runtime, and from .NET 8 BinaryFormatter throws across nearly all project types, with .NET 9 removing the in-box implementation [7], [8] (Ec9)

1.2.3 Evolution

  • ❌ The language line is closed to new features: Microsoft has stated that Visual Basic will not be evolved for new workloads, and the language receives no new syntax (V3)
  • ✅ The language remains supported for existing code: The compiler is maintained with the .NET SDK for bug fixes and platform compatibility
  • ✅ The runtime advances under the language: An existing assembly runs on a current .NET, so the platform moves even though the language does not
  • ✅ A migration path to C# exists and is close: The language improved substantially from Visual Basic 6, and the constructs and the object model map almost one to one onto C#
  • ⚠️ A new framework feature can be C#-only: Nullable reference types and static abstract interface members arrived without a Visual Basic form
  • ❌ Build variants multiply: #If blocks with compiler constants select which code the compiler emits (V7)

1.2.4 Domain

  • ✅ Office and COM automation is a native domain: Object and late binding make an Office object model usable without an interop assembly
  • ✅ Windows Forms is the rapid-desktop domain: The designer and the event model fit a business form application
  • ✅ Console tools and services are straightforward: A short program builds into an .exe in the .NET toolchain
  • ✅ The .NET library ecosystem is reachable: Any assembly with a public surface can be consumed
  • ⚠️ Modern .NET UI frameworks are not offered for Visual Basic: The .NET MAUI and Blazor templates are C#, so a new Visual Basic GUI is a Windows Forms or WPF project
  • ⚠️ It is not the choice for new development: The language remains less expressive than C# on the newer features, and the direction of the ecosystem is C#

1.2.5 Learning

  • ✅ The syntax is readable and close to English: If ... Then, For Each ... In, and End Sub read as their meaning
  • ✅ The curve is gentle from BASIC or Visual Basic 6: The surface carries over, and the runtime supplies the rest
  • ✅ The reference documentation is complete: Microsoft documents every statement, keyword, and option
  • ✅ The IDE guides a new user: IntelliSense and the compiler’s messages explain a construct as it is written
  • ⚠️ Four Option statements change the language: Strict, Explicit, Infer, and Compare each alter what compiles or what a comparison means
  • ⚠️ The large subject is the class library: The framework, not the syntax, is the bulk of the work

1.2.6 Syntax

  • ❌ The syntax is verbose: Every block closes with its own keyword pair such as End If, End Sub, and Next, and a declaration repeats Dim and As (S1)
  • ✅ Keywords are words: The reading is close to English
  • ✅ A line ends a statement: Continuation is explicit with _
  • ✅ Attributes are written in angle brackets: <Serializable> and <Obsolete("...")> attach metadata to a declaration
  • ⚠️ A file-level Option changes the parse: Option Strict On at the top of a file changes which lines compile
  • ⚠️ The language is case-insensitive: myValue and MyValue name the same variable, so a rename is not caught by the case

1.2.7 Testing

  • ✅ A test framework is available from NuGet: MSTest, NUnit, and xUnit all run against the .NET test SDK
  • ✅ dotnet test runs the suite: Discovery, execution, and the report come from the platform
  • ✅ A test is written in Visual Basic: Attributes such as <TestMethod> mark a test method
  • ✅ The debugger is integrated: A failed test can be stepped through in Visual Studio
  • ✅ An assertion or mocking library is a package: NUnit’s assertions and Moq are consumed from NuGet
  • ⚠️ The default Option Strict Off weakens the test itself: A test project with the default setting can pass a value of a wrong type and notice only at run time

1.2.8 Security

  • ✅ The runtime is memory-safe: No use-after-free and no buffer overrun occurs in safe code, and the language has no pointer type
  • ✅ No unsafe context exists in Visual Basic: The unverifiable memory operations of the runtime are out of reach
  • ✅ The exception path keeps the failure in a value: ex.Message and ex.InnerException carry the detail to a handler
  • ✅ Option Strict On removes the late-bound call: The member is resolved by the compiler rather than by name at run time
  • ⚠️ On Error Resume Next can hide a failure that matters: A suppressed failure leaves the program in a state the next statement does not expect
  • ⚠️ A COM interop boundary is outside the runtime’s checks: A late-bound call crosses into unmanaged code that the type system does not verify

1.4 Profile

Unscored, and kept separate from every score on purpose. The profile records what a mechanism price cannot express: what a running program costs, how well a coding model and an agent work in the language, and whether a safety-critical path exists.

1.4.1 Energy and cost

What this axis asks: what does a running program cost in energy and time?

  • ⚠️ Runs on a virtual machine, above native code in the energy and time benchmarks [9]; a causal re-analysis attributes most of the gap to execution time [10].

1.4.2 AI and agent readiness

What this axis asks: how well does a coding model and an agent work in this language?

  • ⚠️ Moderate training data: models write it competently, with measurable language-specific weakness [11].

What this axis asks: is there a certified or standards-qualified path to a safety-critical system?

  • ⚠️ No certified or standards-qualified path for safety-critical systems.

Verdict: Visual Basic .NET reaches a mid-range core score by inheriting the .NET runtime’s separation of interface from implementation, its collected memory, and its checked types, while keeping the older Visual Basic defaults beside them. The losses are those defaults: Option Strict Off, a Nothing that fits every reference type, unchecked exceptions, a failure a caller may discard, and manual synchronisation. Main strengths: interfaces, Option Strict On, Using for deterministic release, the whole .NET class library, and a mechanical path to C#. Main weaknesses: Option Strict Off defers a conversion to run time, Nothing is not a checked absence, the collector decides when memory returns, a race has no detector, and the language line is closed to new features.
